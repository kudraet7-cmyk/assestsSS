Exam Insight

A teacher uploads an exam paper and a list of who missed what. The app returns four finished documents — a per-student diagnostic, a class-wide analysis, a WeChat-ready parent message, and an annotated answer key.

Repo kudraet7-cmyk/assestsss Branch claude/teacher-exam-analysis-app-lglghd Date 2026-08-15 Status v2 · sample report built

01 The product in one screen

Step 1 Upload Photo, PDF, pasted text, or typed by hand. AI
Step 2 Review Questions, answers and categories — yours to correct. YOU
Step 3 Scores Paste names and the question numbers each missed. YOU
Step 4 Analyze Error distribution, weak categories, practice bank. AI
Step 5 Export Four documents, individually or as one zip. AI

Every AI step lands in an editable table before it becomes a PDF. The teacher is always the last edit, never the AI.

The four deliverables

PDF · per student

Diagnostic report

Missed questions, mapped categories, and a targeted practice set drawn from their own weak spots.

PDF · per class

Class analysis

Error distribution, error rate by category, hardest questions, and where to re-teach.

TXT · per student

Parent message

Warm, jargon-free, 150–250 characters. Copy button, paste straight into WeChat.

PDF · per class

Answer key

Correct answers, explanations, category tags, and the class error rate beside each question.

All four bilingual: Simplified Chinese first, English below.

Model selection

Two tiers, picked per task. A Pro-tier model reads the photographed paper and writes explanations, where accuracy outweighs cost. A Flash-tier model handles categorization, practice generation and parent messages — high volume, tightly constrained by schema. I'll pin exact model IDs against Google's current lineup when Phase 1 starts rather than hardcoding them now; that list moves quickly. All calls use structured output, so we get typed JSON rather than prose we have to parse.

03 The two decisions that matter most

Student names never reach the AI

Names stay in browser memory. Every request to Gemini carries anonymized error patterns — student_07 missed Q3, Q7, Q12 — or no student reference at all. Names are stitched back in locally when the PDF renders.

This isn't only hygiene. It means you can use this with a real class roster without first having a data-handling conversation with your school, and it costs us nothing architecturally.

Practice exercises are generated per category, not per student

The naive build calls Gemini once per student: forty students, forty calls, slow and expensive — and two students with identical weaknesses get different worksheets for no reason.

Instead, once analysis is done we know the full set of weak categories across the class, say fourteen. We generate a practice bank — six exercises per category, in one batched call — then assemble each student's PDF locally from the exercises matching their own weak categories. Difficulty is tiered inside each category, so a student who missed one question there gets the reinforcement item while a student who missed four gets the full ladder.

40 students · ~40 API calls → ~3 API calls

Generation drops from minutes to seconds, cost falls by more than an order of magnitude, and the worksheets become consistent across the class — which is what you want when parents compare notes.

04 Data model

Session  { meta, questions[], students[], taxonomy[], practiceBank, analysis }

Question { number, text, type, options?, correctAnswer?, explanation?,
             categoryIds[], points?, aiConfidence }
Category { id, nameZh, nameEn, kind: 'knowledge' | 'skill', parentId? }
Student  { id, name, wrongQuestions[], absent? }

Analysis { byQuestion[], byCategory[], byStudent[], classStats, heatmap }

Analysis is pure TypeScript — no AI, fully deterministic, unit-testable. That matters more than it sounds: the numbers on a document you send to a parent should be reproducible and explainable, not the output of a language model.

Category taxonomy

Two levels — for maths, 代数 Algebra ▸ 一元二次方程 Quadratic equations — with a second skill tag on each question (计算 Computation, 概念理解 Conceptual, 应用 Application, 审题 Reading the problem).

Gemini proposes the taxonomy from the paper itself; you edit it in Step 2. Saved taxonomies are reusable, so by your third exam in a subject you're mostly confirming rather than authoring — and that reuse is what makes cross-exam comparison possible later.

05 Input formats

The exam paper — three routes, one review table

  1. Photo or PDF upload. Drag in phone photos or a scan. Gemini extracts number, text, options, and the answer if it's printed. Each row carries a confidence score, and anything below threshold is flagged amber — so you check the three rows that need it, not all forty.
  2. Paste plain text. For papers already digital. Cheapest and most accurate path.
  3. Manual builder. Question by question. This is also the edit layer for routes 1 and 2, so it's built once and used everywhere.

If the paper arrives without an answer key

Gemini drafts the answers and flags them unverified; they render with a review marker until you confirm. The answer-key PDF refuses to export while any unverified answer remains. A wrong answer key sent to forty families is the worst failure this app can produce, so it gets a hard gate rather than a warning banner.

Scores — paste roster and numbers

王小明: 3,7,12,15
李思思: 2,3,15
张伟 3 7 9 21
陈静：4、11、23        ← full-width colon and 、 both accepted
刘洋: 无               ← 无 / 满分 / - all mean zero wrong

The parser is deliberately forgiving about separators and stray punctuation, expands ranges like 3-5, and flags duplicate names. It checks every number against the paper's question range and shows a live preview as you type — so Q47 on a 30-question paper surfaces immediately, not inside a finished PDF.

Optional, and the single biggest lever on report quality

王小明: 3B,7C,12A,15D

Appending the letter they chose costs one keystroke per question. Knowing only that Q30 was missed gets you “the answer is connect with”. Knowing they chose B. to gets you “you picked to, which is for connecting devices — connect the printer to the computer; people take with.”

That's the difference between a restatement and a correction. It also lets the class report name which distractor the class fell for — often the single most useful fact from an exam. Entirely optional and per-question: 3B,7,12A is valid, and questions without a letter just get the shorter treatment.

Subjective loss, tracked separately

Your reference report shows 2 objective misses against 84.5 / 100 — leaving 13.5 marks of subjective loss entirely invisible. So the session records a per-student subjective deduction alongside the wrong-question list, and the report names it. Otherwise the document quietly implies a student's only problem is two multiple-choice questions when most of their lost marks are elsewhere.

06 What's in each document

You sent a reference report to work from. It reads as a solid first draft, and the two things you flagged — wasted space and thin content — are both real and both fixable. A rebuilt version of that exact report, same student and same exam, sits in docs/samples/: it carries roughly three times the content in a single page.

What cost space
  • Full-width colored section bars, in four different colors carrying no meaning
  • Four oversized stat tiles for four numbers
  • Single-column full-width lines holding four-word exercises
  • The teacher comment restating every number already in the stat row
  • Section numbering skipping from 一 to 三
What replaced it
  • Hairline rules with small-caps labels; one accent plus semantic red / green / amber
  • One stat strip, plus a distribution track showing where the student sits in the class
  • Two columns throughout; trailing blocks pair up rather than orphaning a page
  • The comment spends its space on diagnosis and the next action instead
  • Nothing is stated twice, and the last page is filled or dropped
What weakened the content
  • Only the correct answer shown — never what the student actually picked
  • A practice item that re-asked the missed question verbatim: connect ___ each other
  • A study tip numbered as if it were an exercise, answered with “no fixed answer”
  • A blanket answer-key dump, identical for every student
  • 13.5 marks of subjective loss invisible behind “2 questions wrong”
What replaced it
  • Their wrong answer beside the right one, an error-cause tag, and why that distractor is wrong
  • Contrast pairs that teach the rule: connect the printer to against connect with friends
  • A three-tier ladder — 基础巩固 → 同类变式 → 中考衔接 — each time-budgeted
  • 主观题订正 filtered to this student, each with the specific defect named
  • Subjective loss surfaced, and three dated tasks a parent can tick off

Density rules every document follows

  • No full-width color section bars — a hairline rule and a small-caps label cost a fifth of the height.
  • One accent, plus semantic red / green / amber. A different color per section carries no information.
  • Two columns wherever items are short.
  • Never state the same number twice.
  • Every section earns its header — a tip dressed as an exercise is padding.
  • Fill the last page or drop it. A page 20% full is the format failing.

Per-student diagnostic · 1–3 pages, density-fit

  • Cover — name, exam, score summary, and a category radar chart, so one glance tells a parent where their child stands.
  • Missed questions — each in full, with the correct answer, a short explanation, and its category tag.
  • Weakness summary — categories ranked by the share of that category's questions missed, not raw counts, which unfairly punish well-represented topics.
  • Targeted practice — 3–6 exercises per weak category, difficulty-laddered.
  • Answer page — last page, so the sheet can be handed over intact and the answers torn off.

Class analysis · 4–5 pages

  • Error rate by question — sorted bars, with a threshold line marking questions more than half the class missed.
  • Error rate by category — the headline chart, normalized by attempt count so a two-question category isn't compared naively against a nine-question one.
  • Student × category heatmap — clusters of struggling students become visible.
  • Distribution histogram with mean, median and σ.
  • Teaching focus — a short written section naming the three categories most worth re-teaching, grounded strictly in the computed numbers.

Parent message

A genuine opening about the child, what went well, one or two concrete areas in plain language (no category codes, no jargon), what practice went home, and a warm close. Tone is tunable — Warm / Neutral / Direct — with a teacher-signature field. Downloadable individually or as a zip, plus a per-student Copy button, since you'll usually paste straight into WeChat from the browser.

Answer key

Every question with its answer, explanation, category tags, and class error rate alongside — so the same document works as your marking reference and as your post-exam review script.

07 The past-paper bank

This is the largest content upgrade available to the product, and it changes the AI's job from generation to retrieval.

An AI-invented practice question is plausible-sounding and unaccountable. A real 上海中考 question carries authentic phrasing, calibrated difficulty, and — critically — provenance: 2021 · 上海中考 · 第 32 题 printed on the page. That label changes how a student and a parent treat the worksheet, and it removes hallucination risk from the highest-stakes part of the document. The exercises also get better as the bank grows, instead of being re-invented every run. 

  真题 PDFs ──▶ same vision parser as §05 ──▶ auto-tag against your taxonomy
   (yours)        (already built in Phase 1)        ──▶ dedupe ──▶ review once
                                                                  │
                                                                  ▼
                                                    item bank (local, reusable)
                                                                  │
  student's weak categories ────── retrieve, difficulty-matched ──┘

Difficulty matching is the part that needs care

Your reference report is a Grade 6 paper. Handing a 六年级 student raw 高考 questions would be discouraging and pedagogically useless. So retrieval is gated on a gradeFloor field, and past-paper items are the top tier of a ladder, never the whole worksheet.

In the sample report, exactly 4 of 20 items sit at 中考 tier, all on the same knowledge points the student actually missed — put off, connect with, concessive although. That ratio is a setting, not a constant.

What I can and can't supply

I can build the ingestion pipeline, the tagging, the dedupe, the retrieval, the difficulty gating, and the provenance stamping.

I can't ship you the corpus. I don't have a licensed, verified set of 上海中考 or 高考 past papers, and inventing citations — printing 2019·上海中考·第 38 题 on a question that isn't one — would be worse than no citation at all. Papers you already own are the input; the app turns them into a reusable bank in one pass.

So in the sample report those four items are marked 中考题型 — 中考-style — rather than given a fabricated year and number. Once your papers are ingested, that tag is replaced automatically by the real source line.

08 Visual design

Futuristic, but you'll be using it at 10pm on a Sunday — so: clean, high-contrast, quiet. Dark-first, a near-black ground with elevated glass panels and hairline borders, and light mode built as a real second theme rather than an afterthought, since you may present this on a classroom projector.

#0A0C10 ground #151A22 panel accent ramp #22D3EE cyan #8B5CF6 violet

One accent gradient, cyan to violet, carries progress, primary actions and data emphasis. Everything else stays neutral — a single accent in a restrained field is what reads as futuristic; five accents read as a toy.

Chart colors are a separate, accessible palette, because half of these PDFs will come out of a school laser printer and the error-rate charts have to survive black and white. Sequential ramps, not rainbow. Inter for Latin, Noto Sans SC for Chinese, a mono face for question numbers and figures, tabular numerals throughout the tables. Motion is limited to step transitions and chart draw-on — nothing loops, nothing pulses.

The wizard rail stays on the left throughout, so you can jump back to Step 2 and fix a category without losing anything downstream. Analysis recomputes on its own.

Phases 3 and 4 are the heavy ones. Phase 2 is where the app first becomes useful to you — worth stopping there and running a real exam through it before we build any PDFs, because what you learn will change what goes into them.

Phase 5 sits deliberately after a working per-student PDF. The bank makes good reports better; it can't rescue a report whose layout and explanations aren't right yet, and building it earlier would mean rebuilding retrieval once the document design settled.

10 Risks, and what we do about them

RiskMitigation
CJK fonts in PDFs — Chinese needs an embedded font, and the full Noto Sans SC is ~10MB Pre-subset to GB2312 plus Latin at build time (~3MB), served once and cached; react-pdf subsets again per document so the PDFs stay small. Budgeted as real Phase 3 work, not an afterthought.
OCR accuracy on phone photos, especially handwriting and maths notation Per-question confidence scoring, amber review rows, and the manual builder always available as an escape hatch. This is the assumption most worth validating early — we test with your actual papers in Phase 1.
Vercel function timeout (60s on Hobby) No long call anywhere. Parsing is chunked by page, generation batched and streamed. The practice-bank design exists partly for this reason.
Hallucinated practice questions or explanations Nothing reaches a PDF without passing a teacher review screen. For maths we request worked solutions and verify numeric answers programmatically where the form allows.
API cost drift Per-session token accounting shown in the UI and a configurable ceiling. A 30-question paper for 40 students should land in the low tens of US cents — I'll measure and report real numbers at the end of Phase 4 rather than promise them now.
Gemini rate limits Exponential backoff, request queueing, and partial-result recovery so a limit hit late in a batch doesn't discard the work already done.

11 Open questions

None of these block Phase 0. All are worth answering by Phase 2.

  1. Subject and grade. Taxonomy quality depends on it, and one sample paper from you is worth more than any amount of guessing.
  2. Class size and exam frequency. Determines whether Phase 6 needs bulk workflows.
  3. Partial credit. Right now a question is right or wrong; essay and calculation questions often aren't. Per-question scores are a contained change — but they make score entry meaningfully slower, so it should be a deliberate choice rather than a default.
  4. Cross-exam progress tracking. Explicitly out of scope for v1 and the most likely v2. The data model is shaped so adding it later means adding a store, not a rewrite.
